# Стиль Spring

## Регистрация компонентов

- Не вводи менеджед бин, если компоненту не нужны другие менеджед бины как зависимости; используй обычный `object`.

## Внедрение зависимостей

- Используй внедрение через конструктор для управляемых Spring-зависимостей.
- Используй внедрение через поля только когда внедрение через конструктор недоступно или несовместимо с жизненным циклом фреймворка либо теста.

## HTTP-клиенты

- При использовании `RestClient`, `WebClient`, `RestTestClient` и `WebTestClient` для статических путей предпочитай простые URI-шаблоны вместо построения URI через `UriBuilder`.
- Предпочитай `RestClient`/`WebClient`, а в HTTP-тестах — `RestTestClient`/`WebTestClient`, вместо `RestTemplate`.

## JDBC

- Если контекст проекта не задаёт другое правило, используй `JdbcClient` для нового или изменяемого SQL-доступа через Spring JDBC.
- Не переписывай существующий рабочий доступ к данным только ради перехода на `JdbcClient`.
- Для маппинга строк выбирай первый подходящий вариант: `JdbcAggregateTemplate.getRowMapper(...)`, затем `DataClassRowMapper`, затем собственный `RowMapper`.

## Kotlin API

- Предпочитай Kotlin-расширения Spring эквивалентным Java-перегрузкам с `Class<T>`; при необходимости импортируй расширение.
